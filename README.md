# Сервис учета кадровых заявлений (Application Track Service)

## Назначение

Приложение **Application Track Service** предназначено для автоматизации процесса подачи, регистрации и обработки кадровых заявлений сотрудников организации. Программа позволяет централизованно учитывать заявления (на отпуск, перевод, увольнение, прием на работу), присваивать им уникальный номер, определять статус и сохранять основные сведения о заявителе.

Начиная с ПР3 приложение построено на объектной модели: сотрудники, заявления, категории и статусы представлены классами Python, а не словарями. Данные по-прежнему хранятся в JSON-файлах.

## Целевая аудитория

- **Сотрудники организации** — подача заявлений и отслеживание их статуса.
- **HR-специалисты и кадровая служба** — регистрация, проверка и обработка заявлений.
- **Руководители подразделений** — согласование заявлений подчиненных.
- **Администраторы системы** — управление пользователями и справочниками.

## Предметная область

Предметная область охватывает процессы кадрового делопроизводства, связанные с обработкой заявлений сотрудников. Кадровое заявление — это официальный запрос сотрудника, требующий регистрации, проверки, согласования и исполнения.

Жизненный цикл заявления включает этапы:

1. Создание и подача заявления сотрудником.
2. Регистрация заявления в системе.
3. Проверка HR-специалистом.
4. Согласование руководителем.
5. Принятие решения (одобрено / отклонено).
6. Исполнение и архивирование.

## Основные классы

### `Employee` — сотрудник

Класс `Employee` представляет сотрудника организации.

Основные атрибуты:

- `id` — уникальный идентификатор сотрудника;
- `fio` — ФИО сотрудника;
- `department` — подразделение;
- `age` — возраст.

Основные методы:

- `__str__()` — строковое представление сотрудника;
- `to_dict()` — преобразование объекта в словарь для сохранения в JSON;
- `from_data(data)` — создание объекта `Employee` из данных JSON (`@classmethod`).

### `Request` — заявление

Класс `Request` представляет кадровое заявление сотрудника. Заявление хранит **ссылку на объект `Employee`**, а не только его идентификатор, что позволяет обращаться к данным сотрудника напрямую: `request.employee.fio`.

Основные атрибуты:

- `id` — уникальный идентификатор заявления;
- `employee` — объект `Employee`, подавший заявление;
- `type` — тип заявления (отпуск, перевод, увольнение, прием на работу);
- `status` — текущий статус заявления;
- `date` — дата подачи заявления.

Основные методы:

- `__str__()` — строковое представление заявления;
- `resolve_type_and_status(choice, employee_age)` — определение типа и начального статуса заявления по коду типа и возрасту сотрудника (`@staticmethod`);
- `to_dict()` — преобразование объекта в словарь для сохранения в JSON (сотрудник сохраняется как `employee_id`);
- `from_data(data, employees)` — создание объекта `Request` из данных JSON с восстановлением связи с объектом `Employee` (`@classmethod`).

### `Category` — категория заявления

Класс `Category` представляет запись справочника категорий (типов) заявлений.

Основные атрибуты: `code`, `name`.

Основные методы: `__str__()`, `to_dict()`, `from_data(data)`.

### `Status` — статус заявления

Класс `Status` представляет запись справочника возможных статусов заявлений.

Основные атрибуты: `code`, `name`.

Основные методы: `__str__()`, `to_dict()`, `from_data(data)`.

## Взаимодействие объектов

```
Request
├── employee → Employee
```

Заявление (`Request`) создаётся на основе существующего сотрудника (`Employee`) и хранит прямую ссылку на объект сотрудника. Благодаря этому данные сотрудника доступны непосредственно через заявление:

```python
request.employee.fio
request.employee.department
```

Это исключает необходимость передавать отдельно коллекцию сотрудников в функции поиска, вывода и сортировки заявлений — им достаточно коллекции объектов `Request`.

## Основные функции

### `employees.py`

- **`Employee`** — класс сотрудника (см. раздел «Основные классы»).
- **`get_next_employee_id(employees)`** — возвращает следующий свободный ID сотрудника.
- **`find_employee_by_id(employees, employee_id)`** — находит объект `Employee` по идентификатору.
- **`add_employee(employees, employee_id, fio, department, age)`** — создаёт объект `Employee` и добавляет его в коллекцию.
- **`find_employees(employees, query)`** — ищет сотрудников по ФИО или подразделению.
- **`show_employees(employees)`** — выводит список сотрудников на экран.
- **`sort_employees_by_age(employees)`** — сортирует сотрудников по возрасту.

### `requests.py`

- **`Request`** — класс заявления (см. раздел «Основные классы»).
- **`get_next_request_id(requests)`** — возвращает следующий свободный номер заявления.
- **`create_request(requests, employees, employee_id, choice)`** — создаёт объект `Request`, связывая его с объектом `Employee`.
- **`cancel_request(requests, request_id)`** — удаляет заявление по номеру.
- **`find_requests(requests, query)`** — ищет заявления по ФИО сотрудника, типу или статусу.
- **`sort_requests(requests, sort_choice)`** — сортирует заявления по дате, типу или статусу.
- **`get_request_statistics(requests)`** — формирует статистику заявлений по типам.
- **`show_requests(requests)`** — выводит заявления на экран.

### `categories.py`

- **`Category`** — класс категории заявления.
- **`load_categories(filename)` / `save_categories(categories, filename)`** — загрузка и сохранение справочника категорий.
- **`get_category_name(categories, code)`** — возвращает название категории по коду.
- **`find_category(categories, query)`** — ищет категории по названию.
- **`show_categories(categories)`** — выводит категории на экран.

### `statuses.py`

- **`Status`** — класс статуса заявления.
- **`load_statuses(filename)` / `save_statuses(statuses, filename)`** — загрузка и сохранение справочника статусов.
- **`get_status_name(statuses, code)`** — возвращает название статуса по коду.
- **`find_status(statuses, query)`** — ищет статусы по названию.
- **`show_statuses(statuses)`** — выводит статусы на экран.

### `storage.py`

- **`load_json(filename, default)`** — загружает список из JSON-файла.
- **`save_json(filename, data)`** — сохраняет список в JSON-файл.
- **`load_employees(filename)` / `save_employees(filename, employees)`** — загрузка JSON в объекты `Employee` и сохранение обратно.
- **`load_requests(filename, employees)` / `save_requests(filename, requests)`** — загрузка JSON в объекты `Request` со связью с объектами `Employee`, и сохранение обратно.

### `utils.py`

- **`input_non_empty(prompt)`** — безопасный ввод непустой строки.
- **`input_int(prompt, min_value, max_value)`** — безопасный ввод целого числа с проверкой диапазона.
- **`input_choice(prompt, choices)`** — ввод одного значения из набора допустимых вариантов.

## Тестирование

В проекте используются тесты на `pytest`. Запуск:

```bash
python -m pytest
```

Или просто:

```bash
pytest
```

Тесты покрывают:

- создание объектов и работу с сотрудниками (`tests/test_employees.py`);
- создание объектов и работу с заявлениями, включая связь с сотрудником (`tests/test_requests.py`);
- работу со справочником категорий (`tests/test_categories.py`);
- работу со справочником статусов (`tests/test_statuses.py`).

Для проверки стиля используется `flake8`:

```bash
flake8 .
```

## Данные

Все данные хранятся в папке `data/` в формате JSON:

- `data/employees.json` — список сотрудников;
- `data/requests.json` — список заявлений (хранит `employee_id`, а не вложенный объект);
- `data/categories.json` — справочник категорий заявлений;
- `data/statuses.json` — справочник статусов заявлений.

При загрузке данные из JSON преобразуются в объекты классов `Employee`, `Request`, `Category` и `Status`. При сохранении объекты преобразуются обратно в структуры JSON. Файлы создаются автоматически при первом сохранении, если их нет.

## Веб-версия на Django

Веб-версия добавлена как отдельный интерфейс к существующей предметной модели.
Консольная программа и JSON-хранилище сохранены; перенос данных на Django ORM
не входит в этот этап.

Для запуска установите зависимости и запустите сервер разработки:

```bash
python -m pip install -r requirements.txt
python manage.py runserver
```

Основные страницы:

- `/` — главная страница со сводкой;
- `/employees/` — список сотрудников с поиском;
- `/employees/<id>/` — карточка сотрудника;
- `/requests/` — список заявлений с поиском;
- `/requests/<id>/` — карточка заявления.

Пакет `hr_service` содержит настройки и корневую маршрутизацию Django.
Приложения `homepage`, `employees_web` и `applications` отвечают за главную
страницу, сотрудников и кадровые заявления соответственно.
